# Code and data for "Post-Training Quantization of a Depthwise Separable Seismic Phase Picker for TinyML Deployment: Accuracy, Latency and Energy"

Pre-release collection for the Data and Code Availability statement of the manuscript. **Status: staging folder, not yet published** (see "Before publishing").

## What is here

| Folder | Content |
|---|---|
| `scripts/core/` | modules imported by every script (`config.py`, `data.py`, `data3ch.py`, `model.py`, `phasenet_keras.py`) |
| `scripts/pipeline/` | training, post-training quantization (16x8, INT8, W4A8 emulation), firmware input generation |
| `scripts/paper/` | scripts that produce every table, number macro and figure of the manuscript |
| `firmware/` | ESP32-S3 firmware (PlatformIO, ESP-IDF 4.4.7, esp-tflite-micro 1.3.4, ESP-NN 1.2.9), including the replacement transposed-convolution kernel (`src/transpose_conv_act_fix.cc`), the operator profiler and the hash test; `results_hw/` holds the raw device logs |
| `results/` | final result files read by the paper scripts |
| `models/` | trained models for seeds 42, 43 and 44 (Keras and TFLite) |
| `data/` | what is and is not redistributed (see `data/README.md`) |
| `supplement/` | supplementary data of the manuscript: `per_seed_results.csv` (measurements on the device for each seed, with mean and sample standard deviation; generated by `scripts/paper/189_suplemen_per_seed.py`) |

`CHECKSUMS.sha256` lists SHA-256 of every file and `PROVENANCE.tsv` the origin of every file in the authors' working repository (last commit and its date, number of commits, SHA-256).

Names: the model of the manuscript is called TinyPhaseNet throughout; internal working names of the authors' repository were replaced by `tinyphasenet` in file names (for example `include/tinyphasenet_16x8_model.h`, `models/tinyphasenet_16x8.tflite`) and in the text of the scripts. Code comments, docstrings and console messages are in English; the serial output of the firmware (for example the end-of-session markers `Profiling selesai` and `Benchmark selesai`, which the measurement scripts wait for) and the Indonesian-language labels written by the `*_id` outputs of the table scripts are kept as they are, because the device logs and the Indonesian manuscript depend on them. The raw device logs in `firmware/results_hw/` are kept as recorded and still show the firmware project name `phasenet_z_profiling_v2` in the boot line.

## Reproducing the tables and figures

```
python3 reproduce.py --python /path/to/python
```

The Python needs numpy, matplotlib and tensorflow (TensorFlow is only used to read the Keras models, for the architecture diagram and the parameter counts of the depthwise separable comparison). The script copies `results/` into `_work/`, links `models/` and `firmware/`, runs the paper scripts in order and writes the tables, number macros and figures to `_work/draft_publikasi_1/tabel_dev/`. With `--compare <folder>` it compares the generated `.tex` files with a reference folder; for the manuscript sources all 20 generated files were identical on the last check.

## Companion study (compression, no device)

A second manuscript uses the same models and results to study the two compression steps without the device: depthwise separable against standard convolutions, and post-training quantization (16x8, INT8, W4A16, W4A8) applied to both. Its scripts are in this folder too:

- `scripts/pipeline/199_ptq_padrao.py` quantizes the standard-convolution models (`models/ablation_final/standard_seed*.keras` and `pn_seed*.keras`) into `models/quant_padrao/` and evaluates F1-score and arrival-time picking on the four datasets; `197_picking_formatos.py` and `203_picking_w4a16_separable.py` do the same for the depthwise separable formats (needs the dataset caches, see `data/README.md`). Their outputs are in `results/final/` (`ptq_padrao_3seed.json`, `picking_formatos*.json`, `picking_w4a16_separable.json`).
- `scripts/paper/202_mac_flops.py` (MACs and FLOPs from the TFLite graph, checked against an analytic count), `196_tabel_pendamping.py`, `198_tabel_picking_formatos.py` and `201_tabel_tangga.py` build every table, number macro and figure of that manuscript from those results; `reproduce.py` runs them and writes `_work/draft_publikasi_1/tabel_pend/` (compare with `--compare-pend`).
- 4-bit formats (W4A16, W4A8) are emulations of accuracy: the quantized weights are stored one per byte and no runtime executes 4-bit convolutions; their file sizes in the tables are theoretical (two weights per byte).

## Rebuilding the firmware and repeating the measurements

1. Install PlatformIO and a toolchain for ESP-IDF 4.4.7 (ESP32-S3).
2. Regenerate the window headers (`hw_eval_stead.h`, `hw_eval_instance.h`, `hw_eval_ethz.h`) with `scripts/pipeline/10_make_hw_eval_inputs.py` (needs the dataset caches, see `data/README.md`); the model headers for the other environments (`3ch_int8`, `fp32_*`) come from `163_make_fw_int8_final.py`, `165_make_fw_3ch_int8.py` and `170_make_fw_float32.py`. Run the scripts from a tree laid out like `reproduce.py` builds it (scripts flat, `results/`, `models/`, `data/`, `firmware/tinyphasenet_profiling/`).
3. `pio run -e <env> -t upload`, where `<env>` is one of the environments in `firmware/platformio.ini` (`int8`, `16x8`, `3ch_*`, `fp32_*`, `prof_*` for the operator profile, `*_hash*` for the kernel equivalence test, `*_sram` for the arena location).
4. Read the serial output with `firmware/read_serial.py`. The board is an ESP32-S3-DevKitC-1 with 8 MB octal PSRAM and an INA219 current sensor on the board supply; the logs in `firmware/results_hw/` are the sessions used in the manuscript.

Tested on 28 Nov 2026: `reproduce.py` regenerates all 30 table and macro files of `tabel_dev` and 26 of `tabel_pend` identical to those of the manuscript sources, and rebuilds `hw_padrao_kuant_tiga_seed.json` and `pareto_dua_belas.json` identical to the stored versions (the ten remaining `tabel_pend` files come from scripts that are not in this release). Earlier test, on 10 Nov 2026: starting from this folder, the window headers were regenerated (identical to the originals except the per-seed 16x8 threshold and Python scores; the generated 3-channel INT8 headers are byte-identical to those generated from the original working folder), and eight environments build successfully for the ESP32-S3: `int8`, `prof_1ch_16x8`, `3ch_int8`, `fp32_1ch`, `fp32_3ch`, `int8_hash`, `prof_var` and `3ch_16x8_sram` (at least one per group; PlatformIO downloads the toolchain and the esp-tflite-micro and ESP-NN components). The remaining environments were not built from this folder. Only the `int8` and `prof_1ch_16x8` builds were made without any file from outside this folder; the 3-channel environments also needed `hw_eval_3ch_100.h` (see "Known gaps").

### Models with standard convolutions (Float32)

`scripts/pipeline/191_make_fw_float32_standard.py <include folder of a copy of the firmware> <seed>` writes the model and window headers (`phasenet_fp32_{1ch,3ch}_model.h`, `hw_eval_fp32_{1ch,3ch}.h`) for the standard-convolution models (single-channel: the PhaseNet Q architecture with standard convolutions; three-channel: the PhaseNet architecture retrained with the same recipe). It needs the STEAD data. Build `fp32s_1ch` (arena in internal SRAM) and `fp32f_3ch` (arena in PSRAM), both with the replacement kernel. The three-channel firmware is larger than the 3 MB application partition of `huge_app.csv`; in the working copy replace that file by `huge_app_6mb.csv` (copied as `huge_app.csv`) before building. `scripts/paper/192_ringkas_hw_padrao_tiga_seed.py` summarises the three-seed device logs `sesi_10nov_padrao_*`.

### Standard-convolution models in 16x8 and INT8 (twelve configurations)

The PhaseNet counterparts (standard convolutions) were also measured in 16x8 and INT8, single-channel and three-channel, for seeds 42, 43 and 44 (sessions of 27 Nov 2026), so that all twelve configurations (TinyPhaseNet and PhaseNet, each in Float32, 16x8 and INT8, with one and three channels) are measured on the device.

- `scripts/pipeline/230_make_fw_standar.py <include folder of a copy of the firmware> <1ch|3ch> [seed]` writes the model headers (same file and symbol names as the TinyPhaseNet variants, so the environments `int8`, `16x8`, `3ch_int8` and `3ch_16x8` of `firmware/platformio.ini` are used unchanged) and the 100-window inputs from `models/quant_padrao/*.tflite` and the thresholds in `results/final/ptq_padrao_3seed.json`.
- `firmware/skrip_ukur_standar/` holds the measurement scripts (`jalan.sh` for one session, `semua.sh` for the twelve sessions, `ukur.py` to read the serial port without resetting the board) and `main_3ch_16x8_wdt.cpp`, the three-channel 16x8 firmware with the idle-task watchdog of the second core disabled (one invocation of that model takes 9.2 s). Set `PORT` and `WORK` as described in `jalan.sh`.
- The raw logs are `firmware/results_hw/sesi_27nov_padrao_seed*_*_stead.log`. `scripts/paper/231_ringkas_hw_padrao_kuantisasi.py` reads them and writes `results/final/hw_padrao_kuant_tiga_seed.json` (per seed, mean and sample standard deviation, ratio to the separable counterpart); `232_pareto_dua_belas.py` builds the Pareto analysis of the twelve configurations (`results/final/pareto_dua_belas.json`, 3^12 = 531,441 seed combinations); `234_sinkron_draf_perangkat.py` writes the twelve-row device table, the number macros and the Pareto figure of the manuscript.
- 4-bit formats are not measured on the device (emulation only).

### Companion study: simulation against measurement

`scripts/paper/235_sandingan_draf_pendamping.py` builds the table that sets the simulated latency and energy of the ESP32-S3 (static count and analytical model, `results/final/simulasi_biaya_mcu.json`, `xtensa_instruksi.json`, `mac_flops.json`) against the twelve measured configurations, and its number macros; `236_gambar_protokol_sederhana.py` draws the data and processing figure of the companion study. The simulation scripts themselves are not part of this release.

### Statistics and Pareto analysis

`scripts/paper/190_ketidakpastian_statistik.py` (bootstrap intervals of the device F1-score; Pareto robustness over the six depthwise separable configurations) and `scripts/paper/193_pareto_delapan.py` (Pareto front, seed robustness and selection rules over the eight configurations measured on the device) run from `reproduce.py` and write the number macros read by the manuscript.

`scripts/paper/194_tabel_picking.py` builds the arrival-time (picking) table of the single-channel Float32 model from `results/final/picking_per_seed.json`; the F1-score per dataset of every model and format in the manuscript is produced by `scripts/paper/187_tabel_depthwise.py`.

`scripts/paper/195_simulasi_perencana_tflm.py` simulates the greedy memory planner of TensorFlow Lite Micro on the four Float32 graphs; it reproduces the planned arena layout of the three-channel standard model exactly (39 of 39 offsets of the plan printed by the board, `firmware/results_hw/sesi_10nov_rencana_memori_3ch_standar_seed44.log`) and explains why its arena is larger than that of its depthwise separable counterpart.

### Kernel equivalence test on a computer

`sh firmware/teste_kernel_host/jalankan.sh` compiles the replacement kernel together with the reference kernels of the runtime and compares them on 25,600 random tensors per format (INT8, 16x8 and Float32). It needs `firmware/managed_components/espressif__esp-tflite-micro`, which PlatformIO creates on the first firmware build. `firmware/teste_kernel_host/RESULTADO.txt` records the results: identical outputs for INT8 and 16x8, and for Float32 unless the compiler is allowed to fuse multiply-add.

## Provenance and history

`PROVENANCE.tsv` lists, for every file, its path in the working repository, whether git tracks it there, the last commit hash and date, the number of commits that touched it, and whether it had uncommitted changes when this folder was built. Commit messages are deliberately not copied. This folder is itself a git repository, so changes made from now on are versioned here.

## Known gaps

- `hw_eval_3ch_100.h` (the 100 three-channel STEAD windows, 5.3 MB) has no generating script anywhere in the working repository or its git history; it is not included (it contains STEAD data). The environments `3ch_16x8` and `3ch_int8` need it, so they cannot be rebuilt from scratch from this folder. `165_make_fw_3ch_int8.py` also reads it for a consistency check, which prints a deviation of 0.82 against the old stored scores; the same value is printed when the script runs from the original folder (the old header predates the final model).
- The model headers in `firmware/include/` are copies of the working state (they are regenerated per seed by the `make_fw` scripts) and may correspond to the last seed run, not necessarily seed 42.
- 186 of the 272 files (device logs, trained models, two headers and `sdkconfig.3ch_16x8`) are not tracked by git in the working repository; their history starts in this folder.
- Training and quantization were checked for presence and imports only; they were not re-run to confirm bit-identical weights.
